# Claude emits Resume Structure; the app owns all LaTeX rendering

Claude never writes LaTeX. It produces **Resume Structure** (structured content JSON — name, contact, sections, entries, bullets), and the app deterministically renders that into `main.tex` by calling the template's fixed macros with escaped values. We rejected letting Claude write raw `.tex` directly: user content contains LaTeX-special characters (`& % $ # _ { } ~ ^ \`) that would silently break compilation or inject commands, and a single malformed bracket from the model yields a resume that won't compile at all. Escaping is a solved, testable function owned by the app; correctness is not left to the model. This reuses the existing forced-tool-call pattern — the tool schema changes from a `paragraphs[]` array to a Resume Structure object.
