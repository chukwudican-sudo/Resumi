# Compile LaTeX to PDF server-side via Tectonic (replaces in-browser WASM)

The original decision (compile in the browser via SwiftLaTeX WASM) was reversed. The WASM bundle depended on the dead `texlive2.swiftlatex.com` package server and produced unreliable output. We now compile server-side by shelling out to Tectonic (`tectonic -X compile`) from a Next.js API route (`/api/compile`). Tectonic resolves and caches its own package bundle on first run, produces clean PDF output, and requires no external package mirror. The client-only/offline requirement was dropped — the tool already requires the Anthropic API, so a server-side compile step adds no meaningful privacy regression. The compile route streams the PDF bytes back directly; the client creates an object URL and renders it in an `<iframe>`. First compile on a fresh machine is slow (package bundle download); subsequent compiles are fast.
